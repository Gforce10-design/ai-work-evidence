2장 — CLAUDE.md를 오래 고쳐 쓸 수 있게 짜기

기술 검증판 2026-09-28 · 원고 최종 수정 2026-09-28

증상
사고가 날 때마다 규칙을 덧붙이다 보니 CLAUDE.md 가 감당 못 할 크기가 됐다
원인
한 파일에 모든 규칙을 쌓으면 프로젝트마다 다른 요구를 담을 자리가 없다
붙일 장치
얇은 부트스트랩 + 외부 정본 포인터 + 해시 고정 + 마커 블록 조각
그래도 부족했던 것
모든 프로젝트가 정본을 토씨 하나 안 틀리고 쓰고 싶어 하지는 않는다

증상

세 달 전에 처음 만든 CLAUDE.md는 스무 줄짜리였다. "이 저장소는 이런 구조다", "커밋 전엔 테스트를 돌려라" 정도. 그런데 프로젝트를 진행하며 사고가 하나씩 났고 사고가 날 때마다 규칙을 한 단락씩 추가했다. 서브에이전트가 승인 없이 프로덕션에 배포한 날엔 "배포 전 오너 승인" 단락이, 세션이 끊겨서 이미 기각된 설계를 다시 꺼내온 날엔 "세션 인계" 단락이 붙었다. 지금 그 파일은 500줄이 넘는다.

그 500줄을 이제는 아무도 못 건드린다. 어느 단락을 지워도 되는지 아무도 모른다. "이 규칙 아직도 유효한가?"라는 질문에 답하려면 git blame으로 그 단락이 언제 왜 들어갔는지 추적해야 하는데 커밋 메시지는 대개 "CLAUDE.md 업데이트"다. 그리고 이 파일을 쓰는 프로젝트가 하나가 아니다. 새 프로젝트를 시작할 때마다 마음에 드는 단락을 복사해 붙여넣었고, 반년이 지난 지금 프로젝트 A의 "에이전트 루프" 절과 프로젝트 B의 "에이전트 루프" 절은 미묘하게 다른 버전이 됐다. 어느 쪽이 최신인지, 어느 쪽에 나중에 잡힌 버그 수정이 반영됐는지 아무도 모른다.

가장 나쁜 경우는 따로 있다. 어느 날 "서브에이전트에게 절대 위임하지 말고 혼자 다 처리하라"는 절과 "큰 작업은 반드시 서브에이전트에 위임하라"는 절이 같은 파일에 동시에 존재한다는 걸 발견했다. 둘 다 각자 다른 시점에, 각자 다른 문제를 풀려고 합리적으로 추가된 문장이었다. 그런데 합쳐 놓으니 에이전트가 매번 둘 중 하나를 임의로 고르는 상태가 됐다.

왜 그런가

코드는 모듈·버전·의존성을 도구로 관리할 수 있다. 언어와 도구에 따라 잘못된 import는 빌드나 실행 때 드러난다. 그런데 여기의 규칙 문서는 그냥 텍스트다. 모순되는 두 문장을 같은 파일에 넣어도 에러 하나 나지 않는다. 프로젝트 A의 절을 복사해 프로젝트 B에 붙여넣어도 "이 사본은 원본의 v3 시점 것"이라는 정보가 어디에도 남지 않는다. 지워도 되는 단락과 지우면 안 되는 단락을 구분할 메타데이터가 없다.

즉 우리는 문서를 코드처럼 다루지 않았다. 코드였다면 당연히 있었을 것들이 규칙 문서에는 하나도 없다 — 모듈 경계, 버전 태그, 의존성 검사, 배타 관계 선언. 이 장에서는 그 네 가지를 규칙 문서에도 적용해 본다. 아래 예제는 정본 해시 대조와 조각 간 배타 검사까지만 구현한다. 조각의 선행 의존성 그래프나 버전 호환성까지 검사하는 패키지 관리자는 아니다.

최소 해법 — thin bootstrap + 외부 정본 포인터

가장 단순한 형태부터 시작한다. 프로젝트 파일에는 규칙을 아예 적지 않는다. 대신 정본이 어디 있는지, 몇 번째 버전인지 적고 기록한 바이트와 일치하는지는 해시값으로 확인한다. 해시는 작성자 신원이나 문서의 안전성을 증명하지 않는다.

~/project/CLAUDE.md에 둘 파일:

# 프로젝트 부트스트랩
CANONICAL_PATH=~/policies/team-rules.md
CANONICAL_VERSION=1.0.0
CANONICAL_SHA256=<team-rules.md의 sha256>

이 세 변수명은 Claude Code의 내장 로딩 문법이 아니다. 이 값만 적어서는 정본이 자동으로 읽히지 않는다. 세션 시작 절차에서 검사기를 실행하고, 성공했을 때 그 파일을 읽도록 별도로 연결해야 한다. 자동 import를 쓰려면 공식 @path 문법과 외부 파일 승인 절차를 확인한다.

그리고 이 포인터가 실제로 가리키는 파일과 일치하는지 확인하는 스크립트를 하나 둔다. ~/project/tools/check_canonical.py:

#!/usr/bin/env python3
"""정본 포인터 드리프트 검사기.

CLAUDE.md 안의 "CANONICAL_PATH=... CANONICAL_VERSION=... CANONICAL_SHA256=..."
세 줄을 읽어, 실제 정본 파일의 현재 해시와 대조한다. 다르면 종료코드 1.

사용: python3 tools/check_canonical.py CLAUDE.md
"""
from __future__ import annotations

import hashlib
import re
import sys
from pathlib import Path


def read_pins(bootstrap_text: str) -> dict[str, str]:
    pins = {}
    for key in ("CANONICAL_PATH", "CANONICAL_VERSION", "CANONICAL_SHA256"):
        m = re.search(rf"{key}=(\S+)", bootstrap_text)
        if not m:
            sys.exit(f"[error] {key} 핀을 찾지 못했습니다")
        pins[key] = m.group(1)
    return pins


def main() -> int:
    bootstrap = Path(sys.argv[1] if len(sys.argv) > 1 else "CLAUDE.md")
    pins = read_pins(bootstrap.read_text(encoding="utf-8"))
    canonical = Path(pins["CANONICAL_PATH"]).expanduser()
    if not canonical.is_file():
        print(f"[FAIL] 정본 파일이 없습니다: {canonical}")
        return 1
    actual = hashlib.sha256(canonical.read_bytes()).hexdigest()
    if actual != pins["CANONICAL_SHA256"]:
        print(f"[FAIL] 해시 불일치 — 핀에 기록한 바이트와 다릅니다 (버전 라벨 {pins['CANONICAL_VERSION']})")
        print(f"  핀    : {pins['CANONICAL_SHA256']}")
        print(f"  실제  : {actual}")
        print("  → 정본을 읽고 CLAUDE.md의 CANONICAL_VERSION·CANONICAL_SHA256을 갱신하세요")
        return 1
    print(f"[OK] 핀 해시 일치 ({canonical}, 버전 라벨 {pins['CANONICAL_VERSION']})")
    return 0


if __name__ == "__main__":
    sys.exit(main())

이걸 돌려보면 정본 파일을 아무도 모르게 고쳤을 때 무슨 일이 일어나는지 바로 보인다. 처음엔 해시가 일치해 [OK]가 뜨고, 정본에 몰래 한 줄을 추가한 뒤 다시 돌리면 [FAIL]이 뜨면서 실제 해시와 핀 해시를 나란히 보여준다. 이게 핵심이다 — 프로젝트 파일과 정본이 어긋나는 일을 "아무도 모르는 상태"에서 "스크립트가 즉시 잡는 상태"로 바꿨다. 이제 문서 드리프트를 검출할 수 있다.

이 검사기는 버전 라벨을 정본 내용과 대조하지 않는다. 경로에 공백을 넣는 형식과 중복 핀도 지원하지 않는 최소 예제다. 해시가 다르면 변경 내용을 읽고 승인된 버전인지 확인한 뒤 핀을 갱신한다. 불일치 자체를 없애려고 새 해시만 복사해서는 안 된다.

이 상태만으로도 얻는 게 있다. 여러 프로젝트가 같은 CANONICAL_PATH를 가리키면 규칙을 고칠 곳은 하나뿐이다. 본문 복사로 사본이 갈라지는 일을 줄일 수 있다. 각 프로젝트가 실제로 같은 경로를 읽고 검사기를 실행하는지는 따로 확인해야 한다.

그걸로 부족했던 지점

하지만 어느 프로젝트에서나 정본을 토씨 하나 안 틀리고 그대로 쓰고 싶은 건 아니다. 어떤 폴더는 완료조건 기반 자율 루프가 필요하고, 어떤 폴더는 필요 없다. 어떤 폴더는 서브에이전트에 위임하는 정책이 필요하고, 어떤 폴더는 혼자 다 처리해야 한다. 정본 하나로는 이 편차를 담을 수 없다. 그렇다고 다시 프로젝트마다 손으로 짜깁기하면 1절의 문제로 고스란히 되돌아간다.

그래서 조각 단위 구성(composable fragment)이 필요하다. 규칙을 한 파일에 통째로 두지 않고 독립적으로 넣고 뺄 수 있는 블록의 집합으로 다룬다. 각 블록은 시작과 끝을 HTML 주석 마커로 표시한다.

## 에이전트 루프

목표는 검증 가능한 완료조건과 함께 받는다. 완료조건 없는 목표는 시작 전에 되물어
확정한다. 산출물마다 [생성 → 채점표 검수 → 미달 지적 → 수정] 루프를 돌고, 전 항목
통과라야 합격이다. 산출물별 이터레이션 상한을 정해두고 도달하면 멈추고 보고한다.

실물 산출물이 있어야 완료다. "텍스트만 주고 사용자가 수동으로" 넘기는 것은 미완이다.

마커가 있으면 설치기가 그 블록만 정확히 찾아 치환하거나 삭제할 수 있다. 대신 사람이 손으로 이 블록 안을 고치면 안 된다는 규율이 따른다 — 손으로 고친 순간 그 블록은 더 이상 "카탈로그의 몇 번째 버전"이 아니라 정체불명의 텍스트가 된다. 다음 설치 때 설치기가 그 수정을 덮어쓰거나 반대로 감지를 못 해 블록을 낡은 채로 방치한다. 마커 블록은 "이 구간은 기계가 관리한다"는 경계선이다.

두 번째로 배타 규칙이 필요하다. 1절에서는 "단독 실행 원칙"과 "멀티에이전트 위임 원칙"이 같은 파일에 공존하는 사고를 실제로 겪었다. 이런 사고는 마커만으로는 안 막힌다. 두 블록 다 문법적으로는 멀쩡하기 때문이다. 막으려면 조각마다 "이 조각은 어느 카테고리 소속인가"를 선언하고 같은 카테고리의 조각을 동시에 설치하려 하면 설치기가 거부해야 한다. 이 책은 이 카테고리를 코너(corner)라고 부른다 — 같은 코너에는 한 조각만 설치할 수 있다는 은유다. "실행 구조" 코너에 단독 실행과 멀티에이전트가 있으면 둘 중 하나만 고를 수 있다. "연속성" 코너에 세션 인계 조각이 있으면 그건 실행 구조와 무관하니 자유롭게 같이 설치된다.

배타 검사는 반드시 쓰기 전에 마쳐야 한다. 조각 두 개를 설치하라고 시켰는데 첫 번째는 이미 파일에 써넣고 두 번째에서 거부하면 파일은 절반만 설치된 어중간한 상태로 남는다. 그러면 사용자는 "설치가 실패했다"는 메시지를 봤는데 파일은 이미 바뀌어 있다. 메시지와 파일 상태가 서로 모순된다. 그래서 설치기는 pick 목록 전체에 대해 배타 검사를 먼저 끝내고 문제가 없을 때만 실제 쓰기를 시작해야 한다.

최종형

아래는 실제로 동작하는 조각 설치기 전문이다. 조각은 tools/fragments/<이름>/meta.json (라벨·코너·설명)과 fragment.md(본문) 두 파일로 구성한다.

~/project/tools/claude_md_installer.py:

#!/usr/bin/env python3
"""CLAUDE.md 조각 설치기 — 결정적·마커 기반·코너 배타.

사용법:
    python3 tools/claude_md_installer.py --list
    python3 tools/claude_md_installer.py --target . --pick solo-mode,session-handoff --yes
    python3 tools/claude_md_installer.py --target . --doctor
"""
from __future__ import annotations

import argparse
import json
import re
import sys
from pathlib import Path

SCRIPT_DIR = Path(__file__).resolve().parent
FRAGMENTS_DIR = SCRIPT_DIR / "fragments"
# 도구마다 지침 파일 이름은 다르지만 조각·코너 카탈로그는 하나를 공유한다.
FLAVOR_FILES = {"claude": "CLAUDE.md", "codex": "AGENTS.md"}


def marker(name: str) -> tuple[str, str]:
    return f"<!-- store:{name}:start -->", f"<!-- store:{name}:end -->"


def load_catalog() -> dict[str, dict]:
    catalog: dict[str, dict] = {}
    for meta_path in sorted(FRAGMENTS_DIR.glob("*/meta.json")):
        catalog[meta_path.parent.name] = json.loads(meta_path.read_text(encoding="utf-8"))
    return catalog


def validate_markers(text: str) -> None:
    """중첩·역순·중복·짝 누락을 쓰기 전에 거부한다."""
    opened = None
    seen = set()
    for name, kind in re.findall(r"<!-- store:([a-z0-9-]+):(start|end) -->", text):
        if kind == "start":
            if opened is not None or name in seen:
                raise ValueError(f"중첩 또는 중복 마커: {name}")
            opened = name
            seen.add(name)
        elif opened != name:
            raise ValueError(f"짝 또는 순서가 잘못된 마커: {name}")
        else:
            opened = None
    if opened is not None:
        raise ValueError(f"끝 마커 없음: {opened}")


def installed_names(instr: Path) -> set[str]:
    if not instr.is_file():
        return set()
    text = instr.read_text(encoding="utf-8")
    return set(re.findall(r"<!-- store:([a-z0-9-]+):start -->", text))


def installed_names_all(target: Path) -> set[str]:
    """폴더는 도구가 몇 개든 하나의 작업 공간이다 — CLAUDE.md와 AGENTS.md에 설치된
    조각을 합집합으로 봐야, 한쪽엔 '단독 실행'을 다른 쪽엔 '멀티에이전트'를 심어
    같은 폴더가 서로 다른 도구에서 모순된 지시를 받는 사고를 막는다."""
    names: set[str] = set()
    for fname in FLAVOR_FILES.values():
        names |= installed_names(target / fname)
    return names


def check_exclusions(picks: list[str], installed: set[str], catalog: dict) -> list[str]:
    """같은 코너(corner)는 상호배타. pick끼리 + pick과 기설치 조각을 모두 본다."""
    problems: list[str] = []
    for i, a in enumerate(picks):
        for b in picks[i + 1:]:
            if catalog[a]["corner"] == catalog[b]["corner"]:
                problems.append(
                    f"{a} ↔ {b}: 같은 코너({catalog[a]['corner']}) — 동시 설치 불가")
    for p in picks:
        for existing in installed:
            if existing != p and existing in catalog and catalog[existing]["corner"] == catalog[p]["corner"]:
                problems.append(
                    f"{p}: 이미 설치된 {existing}와 같은 코너({catalog[p]['corner']}) — 설치 불가")
    return problems


def install_fragment(instr: Path, name: str, dry: bool) -> str:
    frag_dir = FRAGMENTS_DIR / name
    body = (frag_dir / "fragment.md").read_text(encoding="utf-8").strip("\n")
    start, end = marker(name)
    block = f"{start}\n{body}\n{end}"
    text = instr.read_text(encoding="utf-8") if instr.is_file() else ""
    validate_markers(text)
    if start in text and end in text:
        pattern = re.escape(start) + r".*?" + re.escape(end)
        new = re.sub(pattern, lambda m: block, text, count=1, flags=re.S)
        action = "교체"
    else:
        new = (text.rstrip("\n") + "\n\n" if text else "") + block + "\n"
        action = "설치"
    if not dry:
        instr.write_text(new, encoding="utf-8")
    return f"{name} {action} → {instr.name}"


def doctor(instr: Path, catalog: dict) -> int:
    """읽기 전용 진단. 아무것도 고치지 않는다. FAIL이 있으면 1을 반환."""
    fails = 0
    if not instr.is_file():
        print(f"  [INFO] {instr.name} 없음 — 설치된 조각 없음")
        return 0
    text = instr.read_text(encoding="utf-8")
    try:
        validate_markers(text)
    except ValueError as exc:
        print(f"  [FAIL] {exc}")
        return 1
    tokens = re.findall(r"<!-- store:([a-z0-9-]+):(start|end) -->", text)
    starts = [n for n, k in tokens if k == "start"]
    ends = [n for n, k in tokens if k == "end"]
    clean: set[str] = set()
    for n in sorted(set(starts) | set(ends)):
        s, e = starts.count(n), ends.count(n)
        if s != e:
            print(f"  [FAIL] '{n}' 마커 짝 깨짐 (start {s} / end {e})")
            fails += 1
        elif s > 1:
            print(f"  [FAIL] '{n}' 블록 중복 {s}개")
            fails += 1
        else:
            clean.add(n)
    for n in sorted(clean):
        start, end = marker(n)
        m = re.search(re.escape(start) + r"\n(.*?)\n" + re.escape(end), text, flags=re.S)
        src = FRAGMENTS_DIR / n / "fragment.md"
        if n not in catalog:
            print(f"  [WARN] 카탈로그에 없는 조각 마커 '{n}'")
        elif not m or not src.is_file():
            print(f"  [FAIL] '{n}' 본문 또는 카탈로그 파일 없음")
            fails += 1
        elif m.group(1) != src.read_text(encoding="utf-8").strip("\n"):
            print(f"  [WARN] '{n}' 블록이 카탈로그 최신본과 다름 — 재설치 권장")
        else:
            print(f"  [OK] '{n}' 정상")
    by_corner: dict[str, list[str]] = {}
    for n in sorted(clean & catalog.keys()):
        by_corner.setdefault(catalog[n]["corner"], []).append(n)
    for corner, names in by_corner.items():
        if len(names) > 1:
            print(f"  [FAIL] 같은 코너({corner}) 조각 공존 — {', '.join(names)}")
            fails += 1
    print(f"\n  진단 결과: {'FAIL ' + str(fails) + '건' if fails else '이상 없음'}")
    return 1 if fails else 0


def main() -> None:
    ap = argparse.ArgumentParser()
    ap.add_argument("--list", action="store_true")
    ap.add_argument("--target")
    ap.add_argument("--pick")
    ap.add_argument("--flavor", choices=sorted(FLAVOR_FILES), default="claude",
                    help="claude=CLAUDE.md(기본) | codex=AGENTS.md")
    ap.add_argument("--doctor", action="store_true")
    ap.add_argument("--yes", action="store_true")
    ap.add_argument("--dry-run", action="store_true")
    args = ap.parse_args()

    catalog = load_catalog()
    if not catalog:
        sys.exit(f"[error] fragments가 없습니다: {FRAGMENTS_DIR}")

    if args.list or not (args.target and args.pick) and not args.doctor:
        for name, m in catalog.items():
            print(f"  {name} — 코너: {m['corner']} — {m['desc']}")
        return

    if not args.target:
        ap.error("--doctor/설치에는 --target이 필요합니다")
    target = Path(args.target).expanduser().resolve()
    instr = target / FLAVOR_FILES[args.flavor]

    if args.doctor:
        sys.exit(doctor(instr, catalog))

    picks = list(dict.fromkeys(p.strip() for p in args.pick.split(",") if p.strip()))
    if not picks:
        ap.error("--pick이 비어 있습니다")
    unknown = [p for p in picks if p not in catalog]
    if unknown:
        sys.exit(f"[error] 없는 품목: {', '.join(unknown)}")

    installed = installed_names_all(target)  # CLAUDE.md + AGENTS.md 합집합
    problems = check_exclusions(picks, installed, catalog)
    if problems:
        print("[배타 위반] 설치를 거부합니다 — 대상 파일은 변경되지 않았습니다:")
        for msg in problems:
            print(f"  · {msg}")
        sys.exit(2)

    if not args.yes and not args.dry_run:
        if input(f"{target} 에 {', '.join(picks)} 설치할까요? [y/N]: ").strip().lower() not in ("y", "yes"):
            sys.exit("취소됨")

    # 입력·마커·조각 파일을 모두 확인한 뒤 메모리에서 한 번에 조립한다.
    original = instr.read_text(encoding="utf-8") if instr.exists() else ""
    try:
        for fname in FLAVOR_FILES.values():
            path = target / fname
            if path.exists():
                validate_markers(path.read_text(encoding="utf-8"))
        bodies = {p: (FRAGMENTS_DIR / p / "fragment.md").read_text(encoding="utf-8").strip("\n") for p in picks}
    except (ValueError, OSError) as exc:
        sys.exit(f"[error] 쓰기 전 검사 실패: {exc}")
    result = original
    messages = []
    for p in picks:
        start, end = marker(p)
        block = f"{start}\n{bodies[p]}\n{end}"
        if start in result:
            result = re.sub(re.escape(start) + r".*?" + re.escape(end), lambda m: block, result, count=1, flags=re.S)
            action = "교체"
        else:
            result = (result.rstrip("\n") + "\n\n" if result else "") + block + "\n"
            action = "설치"
        messages.append(f"{p} {action} → {instr.name}")
    if not args.dry_run:
        import os
        import tempfile
        target.mkdir(parents=True, exist_ok=True)
        fd, staged = tempfile.mkstemp(prefix=".instructions-", dir=target)
        try:
            with os.fdopen(fd, "w", encoding="utf-8") as handle:
                handle.write(result)
            if instr.exists():
                os.chmod(staged, instr.stat().st_mode & 0o777)
            os.replace(staged, instr)
        finally:
            Path(staged).unlink(missing_ok=True)
    for message in messages:
        print(("(dry) " if args.dry_run else "") + message)



if __name__ == "__main__":
    main()

이 설치기는 한 프로세스씩 실행한다. 파일을 교체하기 전에 입력을 전부 확인하고 임시 파일에서 원자적으로 교체하지만, 여러 설치기가 동시에 실행되는 경우의 잠금이나 외부 카탈로그 변조 방어까지 구현하지는 않았다. --flavor는 대상 파일 이름만 고른다. fragment.codex.md를 자동 선택하는 기능은 이 예제에 없다.

조각 예시 세 개. ~/project/tools/fragments/solo-mode/meta.json:

{"label": "단독 실행", "corner": "실행 구조", "desc": "혼자 다 한다 — 다른 워커 호출 없음"}

~/project/tools/fragments/solo-mode/fragment.md:

## 단독 실행 원칙

이 작업 폴더는 서브에이전트를 부르지 않는다. 조사·구현·검증을 전부 같은 세션이 직접 한다.

~/project/tools/fragments/multi-agent/meta.json(같은 코너라서 solo-mode와 동시 설치가 거부된다):

{"label": "멀티에이전트", "corner": "실행 구조", "desc": "오케스트레이터 + 워커 풀로 위임 실행"}

~/project/tools/fragments/session-handoff/meta.json(다른 코너라서 위 둘 중 무엇과도 자유롭게 공존한다):

{"label": "세션 이어가기", "corner": "연속성", "desc": "SESSION.md로 세션 간 인계"}

두 조각의 본문도 필요하다. multi-agent/fragment.md:

## 멀티에이전트 원칙

범위가 분리된 작업만 워커에게 맡긴다. 결과는 검증한 뒤 반영한다.

session-handoff/fragment.md:

## 세션 인계

시작할 때 SESSION.md를 읽고 현재 파일 상태와 대조한다. 마감할 때 현재 상태와 다음 단계를 갱신한다.

같은 정책을 다른 도구에 씌우는 문제도 있다. 예를 들어 Claude Code용 CLI와 다른 CLI 에이전트가 공존하는 저장소가 그렇다. 이 문제는 --flavor 옵션과 installed_names_all()을 함께 써서 해결한다. 정책 문구 자체(조각의 fragment.md)는 두 도구가 같은 걸 쓰되 어느 파일에 심을지만 갈라진다. 코너 배타는 파일 경계를 넘어 폴더 전체에 적용된다. 이 설계가 필요했던 건 집행 메커니즘의 차이 때문이었다 — 똑같이 "사용량 한도에 닿으면 자율 루프를 멈춘다"는 정책을 두 CLI에 심었는데 실측해 보니 한쪽은 표준 훅 구조로 그 정지 신호를 받아 처리했지만 다른 CLI의 자율 루프 런타임은 같은 신호를 무시했다. 그래서 그 CLI에서는 별도의 외부 감시 프로세스가 같은 정책을 대신 집행하도록 조각 자체를 갈랐다. 이 경험은 저자가 운영한 별도 구현의 사례다. 위 최소 설치기는 fragment.md만 읽으며 도구별 변형 선택은 추가 구현이 필요하다. 정책은 하나, 집행 코드는 도구마다 다르다 — 이 원칙을 지키지 않으면 도구를 늘릴 때마다 정책까지 따로 관리하게 된다.

직접 확인하는 법

설치기가 보장한다는 성질 네 가지를 직접 깨뜨려 보고 깨졌을 때 빨간불이 뜨는지 확인한다. fragments/ 아래 조각 서너 개를 위 예시대로 채운 뒤 순서대로 실행한다.

1. 배타가 실제로 막는지. solo-mode를 먼저 설치하고 같은 코너인 multi-agent를 설치해본다.

$ python3 tools/claude_md_installer.py --target proj --pick solo-mode --yes
solo-mode 설치 → CLAUDE.md
$ python3 tools/claude_md_installer.py --target proj --pick multi-agent --yes
[배타 위반] 설치를 거부합니다 — 대상 파일은 변경되지 않았습니다:
  · multi-agent: 이미 설치된 solo-mode와 같은 코너(실행 구조) — 설치 불가

거부 후 proj/CLAUDE.md를 열어 multi-agent 블록이 정말 안 들어갔는지 확인한다. 절반만 쓰인 파일이 아니라 아예 손대지 않은 파일이어야 한다.

2. 재설치가 중복이 아니라 치환인지. 먼저 python3 tools/claude_md_installer.py --target proj --pick session-handoff --yes로 설치한다. tools/fragments/session-handoff/fragment.md 내용을 한 줄 고친 뒤 같은 명령으로 다시 설치한다. grep -c "store:session-handoff:start" proj/CLAUDE.md가 여전히 1을 반환하고 블록 본문이 새 내용인지 확인한다. 2가 나오면 중복 방지에 실패한 것이므로 마커 검색과 치환 경로를 조사한다.

3. 도구 경계를 넘어 배타가 걸리는지. --flavor claude로 solo-mode를 설치한 뒤, --flavor codex로 multi-agent를 설치해본다. 서로 다른 파일(CLAUDE.md와 AGENTS.md)인데도 거부돼야 한다. 거부되지 않고 AGENTS.md가 새로 생겼다면 두 파일을 합친 설치 목록과 코너 비교 로직을 조사한다. 한쪽 파일만 읽는 버그가 원인일 수 있다.

4. doctor가 손댄 흔적을 잡아내는지 — 일부러 깨뜨린다. 설치기를 거치지 않고 CLAUDE.md를 직접 열어 아무 블록이나 통째로 복사해 붙여넣는다(사람이 마커 구간을 손으로 건드리는 사고를 재현한다). 그다음 --doctor를 돌린다.

$ python3 tools/claude_md_installer.py --target proj --doctor
  [FAIL] 중첩 또는 중복 마커: solo-mode

FAIL이 뜨고 종료코드가 0이 아니면 가드가 살아있다. 이 네 단계를 다 통과해야 "설치기가 CLAUDE.md를 코드처럼 다룬다"는 이 장의 주장이 실증된다. 하나라도 조용히 통과(silent pass)한다면 그 파일은 다시 아무도 못 건드리는 텍스트 덩어리로 돌아간다.

정본을 불러오는 공식 문법: CLAUDE.md imports, 확인 2026-09-28. 본문의 핀 검사와 조각 설치기는 이 책의 예제이며 Claude Code 내장 기능이 아니다.
