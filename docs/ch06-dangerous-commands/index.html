6장 — 위험한 명령을 안전하게 위임하기

기술 검증판 2026-09-28 · 원고 최종 수정 2026-09-28

증상
승인 버튼을 하루에 수백 번 누르다 보면 내용을 안 읽고 누르게 된다
원인
확인 창은 마찰만 만들고 판단을 돕지 않는다. 마찰은 곧 무감각이 된다
붙일 장치
위험 명령을 기본 차단하고, 1회성 해시 바인딩 승인 마커로만 열어주는 훅
그래도 부족했던 것
승인 마커 자체가 재사용되면 게이트가 아니다. 소비·만료·정확 일치가 필요했다

증상

멀티에이전트로 여러 작업을 동시에 굴리다 보면 승인 버튼을 누르는 일 자체가 노동이 된다. Bash 명령 하나, 파일 쓰기 하나마다 확인 창이 뜨고 그걸 하루에 수백 번 누르다 보면 손이 먼저 반응한다. 내용을 읽지 않고 누른다. 그러던 어느 날, 브랜치를 정리하던 에이전트가 git push --force를 main에 날렸다. 그 브랜치엔 동료가 사흘 동안 작업한 커밋들이 있었다. 당장 확인한 브랜치 참조에서는 찾을 수 없었다. reflog를 뒤지고 다른 팀원의 로컬 클론을 뒤져서 겨우 절반을 복구했다.

그 뒤로 한동안은 모든 Bash 호출을 손으로 검토했다. 그런데 이건 애초에 자동화를 쓰는 이유 자체를 없앤다. 하룻밤 새 자율적으로 여러 작업을 진행시키려면 사람이 매 명령을 들여다볼 수 없다는 전제가 필요하다. 그렇다고 전부 허용해버리면 다음 사고는 시간문제다. "매번 승인은 귀찮고, 전부 허용은 무섭다" — 이 사이 어딘가에 답이 있어야 했다.

왜 프롬프트 규칙으로는 안 되는가

당연히 처음엔 CLAUDE.md에 "master/main에는 강제 푸시하지 마라"라고 적었다. 1장에서 다룬 것과 같은 이유로 이런 규칙은 세션이 길어지면 흐려진다. 하지만 여기서는 문제가 한 단계 더 심각하다 — 재주입 훅으로 규칙이 흐려지는 걸 막아도 그건 여전히 "모델이 그 순간 그 규칙을 떠올리고 따르기를" 바라는 구조다. 대부분의 작업에는 이 정도 신뢰로 충분하다. 하지만 되돌릴 수 없고 남에게 직접 영향을 주는 명령에는 "대부분"이 기준이 될 수 없다. 강제 푸시는 한 번만 새어나가도 사고다. 아흔아홉 번 잘 지켜졌다고 백 번째 사고가 막히지는 않는다.

그리고 이런 규칙은 컴팩션에 유독 약하다. "지금 이 순간 위험한 명령을 쓰려 한다"는 자각은 압축된 요약 안에 가장 남아 있기 어려운 맥락이다. 결국 진짜 위험한 것들은 모델의 판단이 아니라, 모델이 무엇을 "생각하고 있는지"와 무관하게 항상 같은 자리에서 같은 방식으로 걸리는 구조적 장치로 막아야 한다. Claude Code에는 그 자리가 있다 — 도구 호출이 실제로 실행되기 직전에 끼어드는 PreToolUse 훅이다. 이 훅은 하네스가 실행하는 별도 프로세스이므로, 이번 턴의 컨텍스트와 별개로 실행되지만, 훅의 정상 기동·입력 처리·권한을 확인해야 차단을 신뢰할 수 있다.

최소 해법

PreToolUse 훅은 도구 이름으로 매칭할 수 있고(matcher: "Bash"), 입력으로 tool_input.command에 실행하려는 명령 문자열 전체를 받는다. exit code 2로 종료하면서 stderr에 사유를 쓰면 그 도구 호출은 실행되지 않고 stderr 내용이 모델에게 그대로 전달된다. exit 0이면 평소처럼 진행된다.

여기서는 "무엇을 막을 것인가"를 판단하는 게 결정적이다. 하드셋에 넣는 기준은 딱 두 가지로 좁힌다.

  • 되돌릴 수 없는가. 로컬 브랜치에서 파일 하나를 잘못 지운 건 git checkout 한 번으로 복구되는 경우가 많다. 원격 히스토리를 강제로 덮어쓰는 건 그렇지 않다.
  • 작업 범위를 벗어나 남에게 영향을 주는가. 내 브랜치, 내 로컬 파일을 건드리는 건 실수해도 나만 손해다. origin이나 main처럼 다른 사람이 보고 있는 상태를 건드리는 건 그 순간 남의 작업 환경이 된다.

둘 다 아니면 하드셋에 넣지 않는다. 처음 이 훅을 만들었을 때는 의욕이 앞서서 rm, git reset, git checkout .처럼 "위험해 보이는" 명령을 폭넓게 막아봤다. 하루도 안 돼서 정상적인 로컬 정리 작업까지 전부 막혀버렸고 결국 훅 자체를 꺼버렸다. 그 뒤로 원칙을 바꿨다 — 하드셋은 좁을수록 오래 산다. 넓게 막아서 오작동이 잦아지면 사람은 그 안전장치를 꺼버리고 만다. 그러면 좁게 막았을 때 지켰을 진짜 위험한 몇 가지까지 같이 사라진다. 차라리 처음부터 "이 몇 개만은 절대"로 좁혀서 시작하고 필요하면 사고가 실제로 난 항목만 추가하는 편이 낫다.

이 파일은 ~/.claude/hooks/block_consequential.py에 둔다.

#!/usr/bin/env python3
"""PreToolUse 훅 — Bash 호출 중 좁은 하드셋만 정규식으로 차단한다.

기준: (1) 되돌릴 수 없는가 (2) 내 작업 범위를 벗어나 남에게 영향을 주는가.
둘 다 아니면 이 훅에 넣지 않는다 — 넓게 막으면 결국 훅 자체가 꺼진다.

안전장치: 파싱/로직 에러는 전부 허용(exit 0)으로 떨어진다. 이 훅의 버그가
작업 전체를 마비시켜서는 안 된다.
"""
import json
import re
import sys


def _allow():
    sys.exit(0)


def main():
    try:
        data = json.load(sys.stdin)
    except Exception:
        _allow()

    try:
        if data.get("tool_name") != "Bash":
            _allow()
        cmd = (data.get("tool_input") or {}).get("command", "")
        if not isinstance(cmd, str) or not cmd.strip():
            _allow()

        blocks = []

        if re.search(r"\bgit\s+push\b", cmd):
            if re.search(r"\b(master|main)\b", cmd):
                blocks.append("master/main으로의 git push")
            if re.search(r"--force(-with-lease)?\b|\s-f\b", cmd):
                blocks.append("git force-push")

        if re.search(r"\bgit\s+reset\s+--hard\b", cmd) and re.search(r"\b(origin|upstream)/", cmd):
            blocks.append("원격 ref로의 git reset --hard")

        if re.search(r"\brm\s+-\S*r\S*f|\brm\s+-\S*f\S*r|\brm\s+-rf|\brm\s+-fr", cmd):
            if re.search(r"(^|\s)(/|~|\$HOME)(\s|$|\"|')", cmd):
                blocks.append("홈/루트 대상 rm -rf")

        if blocks:
            sys.stderr.write("BLOCKED: " + "; ".join(blocks) + ".\n")
            sys.exit(2)
    except Exception:
        _allow()
    _allow()


main()

settings.json 배선. 프로젝트 루트의 .claude/settings.json이든 ~/.claude/settings.json이든 형태는 같다.

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "python3 $HOME/.claude/hooks/block_consequential.py"
          }
        ]
      }
    ]
  }
}

이 정규식은 표에 든 단순한 명령 표기만 잡는 보조 검사다. 예를 들어 git -C repo push --force, 기본 대상이 main인 인자 없는 push, 따옴표·변수·별칭·별도 스크립트를 거친 명령은 놓칠 수 있다. 셸 전체를 해석하지 않으므로 위험 명령을 항상 막는 보안 경계로 쓰면 안 된다. 저장소 보호 규칙·도구 권한·OS 격리와 함께 써야 한다.

FAIL-OPEN 설계

위 예제는 입력 파싱이나 로직에서 잡힌 예외를 허용(exit 0)으로 처리한다. 작업 중단을 줄이는 대신 오류가 나면 차단 기능이 사라지는 fail-open 보조 훅이다. 위험한 작업의 유일한 승인 게이트로 쓰기에는 부적합하다.

fail-open이 더 안전하다는 보편적인 결론은 없다. 가용성과 차단 실패의 대가를 나눠 판단해야 한다. 보안 경계로 쓰는 검사는 판정 불가를 허용으로 바꾸지 않아야 하며, 기동 실패·시간 초과도 상위 실행기가 별도로 막아야 한다. 예외 때 exit 2를 내도록 고쳐도 문법 오류나 프로세스 기동 실패까지 자동으로 해결되지는 않는다.

Claude Code의 PreToolUse에서 exit 2는 차단 신호다. JSON 판정이 없는 exit 1은 보통 비차단 오류로 처리된다. 따라서 "프로세스가 실패했다"와 "도구 호출이 막혔다"는 같은 말이 아니다. 아래 실습은 Python 종료코드와 호스트의 차단 처리를 구분한다.

근거: 공식 Hooks reference, 확인 2026-09-28.

그럼 정말 필요할 때는 어떻게 통과하나 — 1회성 승인 마커

하드셋에 걸린 명령이 사실은 지금 진짜로 필요할 때가 있다. 예를 들어 리모트 브랜치가 꼬여서 의도적으로 강제 푸시가 필요할 때가 그렇다. 이럴 때 훅을 통째로 끄는 건 최악의 선택이다 — 그 순간부터 하드셋 전체가 무방비 상태가 된다. "이 명령 하나만, 지금 이 순간만" 통과시키는 좁은 문이 필요하다.

마커 파일을 쓴다. 사람(또는 신뢰된 실행 주체)이 실행하려는 정확한 명령 문자열의 SHA256과 발급 시각, 만료 시각을 JSON 파일에 담아 짧은 시간 동안만 유효하게 만들어둔다. 훅은 그 파일을 확인한 뒤 통과시키면서 그 즉시 파일을 지운다. 세 가지 설계 선택 각각에 이유가 있다.

왜 명령 하나에 정확히 묶는가. "5분간 push는 다 허용" 같은 포괄 승인을 만들면 그 5분 동안 사람이 보지 않은 다른 위험한 명령까지 같이 통과한다. 승인은 사람이 실제로 눈으로 확인한 그 문자열 하나에만 해당하고 그 문자열이 속한 "종류"로는 번지지 않는다. SHA256으로 정확히 묶으면 한 글자만 달라도 승인은 무효가 된다.

왜 TTL(300초)이 필요한가. 마커 파일에 만료 시각이 없으면 예전에 만들어 두고 쓰지 않은 마커가 디스크에 남아 있다가 한참 뒤 완전히 다른 상황에서 그대로 소비될 수 있다. 그 시점엔 애초에 승인했던 맥락 자체가 더 이상 유효하지 않다. 만료 시간을 짧게 잡으면 마커를 "지금 이 순간 승인"으로만 쓸 수 있다.

0600이 보장하는 범위. 다른 OS 사용자의 접근을 제한하지만 같은 사용자 계정으로 실행되는 에이전트와 사람을 구별하지는 못한다. 에이전트가 발급 스크립트나 마커 디렉터리에 쓸 수 있다면 자기 승인을 만들 수 있다. 신뢰된 승인 UI·별도 서비스·OS 권한 경계를 통해 발급 권한을 분리해야 한다. 이 파일 예제 자체는 사람의 승인을 인증하지 않는다.

소비는 원자적으로 한 번만 한다. 읽은 다음 지우기만 하면 두 프로세스가 동시에 읽고 둘 다 통과할 수 있다. 최종형은 먼저 마커를 임의의 소비 경로로 원자적으로 옮긴 프로세스만 읽는다. 유효하지 않은 마커도 소비하며 삭제에 실패하면 승인으로 인정하지 않는다. 마커 디렉터리는 신뢰된 주체만 바꿀 수 있고 소비 경로를 되돌리지 않는다고 전제한다.

명령 해시의 한계. 같은 문자열도 작업 디렉터리·환경변수·PATH·실행 파일·저장소 상태가 달라지면 효과가 달라진다. 이 예제는 문자열만 묶으므로 그런 실행 맥락까지 승인하는 토큰이 아니다. 운영용 승인 기록에는 대상과 실행 맥락도 함께 묶어야 한다.

발급은 사람 또는 분리된 신뢰 주체만 한다. 에이전트에게 차단을 풀기 위해 이 스크립트를 실행하라고 지시하면 안 된다.

발급 스크립트다. 이 파일은 ~/.claude/scripts/approve_once.py에 둔다.

#!/usr/bin/env python3
"""1회성 승인 마커 발행 스크립트.

사용: python3 approve_once.py "<실행할 정확한 명령 전체 문자열>"

이 문자열과 SHA256이 정확히 일치하는 명령 하나만, 발급 시각으로부터 TTL초
안에 통과시키는 마커를 만든다. 훅이 그 마커를 소비하는 순간 파일이 지워진다 —
재사용 불가.
"""
import hashlib
import json
import os
import sys
import time
import tempfile

MARKER = os.path.expanduser("~/.claude/.consequential_allow.json")
TTL_SECONDS = 300


def main():
    if len(sys.argv) != 2:
        sys.exit('사용법: approve_once.py "<정확한 명령 문자열>"')
    command = sys.argv[1]
    now = int(time.time())
    marker = {
        "schema_version": "1",
        "command_sha256": hashlib.sha256(command.encode("utf-8")).hexdigest(),
        "issued_at_epoch": now,
        "expires_at_epoch": now + TTL_SECONDS,
    }
    # 발급 경로는 에이전트와 분리된 신뢰 영역에서만 호출한다.
    directory = os.path.dirname(MARKER)
    os.makedirs(directory, mode=0o700, exist_ok=True)
    fd, staged = tempfile.mkstemp(prefix=".approval-", dir=directory)
    try:
        with os.fdopen(fd, "w", encoding="utf-8") as handle:
            json.dump(marker, handle)
        os.chmod(staged, 0o600)
        os.replace(staged, MARKER)
    finally:
        if os.path.lexists(staged):
            os.unlink(staged)
    print(f"승인 마커 발급: {MARKER} (TTL {TTL_SECONDS}초)")
    print("지금 정확히 이 문자열로 실행해야 한다 — 한 글자라도 다르면 거부된다.")


main()

위 예제는 마커 파일의 생성·해시·만료·소비를 보여준다. 별도 영수증에 누가 승인했는지 써 두는 것만으로 그 신원이 인증되지는 않는다. 0600과 해시를 실제 승인 권한의 대체물로 취급하지 않는다.

최종형

하드셋 차단과 마커 소비를 하나로 합친 최종형이다. 마커 검사가 하드셋 검사보다 먼저 실행된다 — 유효한 마커가 있으면 그 자리에서 통과, 없거나 무효면 그 다음에 하드셋을 검사한다.

이 파일은 ~/.claude/hooks/block_consequential.py에 둔다(최소 버전을 이 내용으로 덮어쓴다).

#!/usr/bin/env python3
"""PreToolUse 훅 — Bash 호출 중 좁은 하드셋만 정규식으로 차단한다.
유효한 1회성 승인 마커가 있으면 정확히 그 명령 하나만 통과시킨다.

기준: (1) 되돌릴 수 없는가 (2) 내 작업 범위를 벗어나 남에게 영향을 주는가.
둘 다 아니면 이 훅에 넣지 않는다.

FAIL-OPEN: 파싱/로직 에러는 전부 허용(exit 0)으로 떨어진다. 이 훅의 버그가
작업 전체를 마비시켜서는 안 된다.
"""
import hashlib
import json
import os
import re
import stat
import sys
import time
import tempfile

MARKER = os.path.expanduser("~/.claude/.consequential_allow.json")
TTL_SECONDS = 300


def _consume_marker(command: str) -> bool:
    """마커를 읽자마자 지운다 — 검증에 실패해도 다시 못 쓰게 만들기 위해서다."""
    raw = b""
    claimed = None
    fd = None
    try:
        # 같은 파일을 두 프로세스가 읽지 않도록 먼저 원자적으로 가져온다.
        fd, claimed = tempfile.mkstemp(prefix=".consumed-", dir=os.path.dirname(MARKER))
        os.close(fd)
        fd = None
        os.replace(MARKER, claimed)
        fd = os.open(claimed, os.O_RDONLY | os.O_NOFOLLOW | os.O_NONBLOCK)
        info = os.fstat(fd)
        if (stat.S_ISREG(info.st_mode) and info.st_uid == os.getuid()
                and stat.S_IMODE(info.st_mode) == 0o600 and info.st_nlink == 1):
            with os.fdopen(fd, "rb") as handle:
                fd = None
                raw = handle.read(8193)
        if len(raw) > 8192:
            raw = b""
    except OSError:
        raw = b""
    finally:
        if fd is not None:
            os.close(fd)
        if claimed is not None:
            try:
                os.unlink(claimed)
            except OSError:
                raw = b""  # 삭제 실패를 승인 성공으로 바꾸지 않는다

    try:
        if not raw:
            return False
        marker = json.loads(raw)
        required = {"schema_version", "command_sha256", "issued_at_epoch", "expires_at_epoch"}
        if set(marker) != required or marker["schema_version"] != "1":
            return False
        if marker["command_sha256"] != hashlib.sha256(command.encode("utf-8")).hexdigest():
            return False
        issued = marker["issued_at_epoch"]
        expires = marker["expires_at_epoch"]
        now = int(time.time())
        if type(issued) is not int or type(expires) is not int:
            return False
        if not (0 <= issued <= now < expires and 0 < expires - issued <= TTL_SECONDS):
            return False
        return True
    except Exception:
        return False


def _allow():
    sys.exit(0)


def main():
    try:
        data = json.load(sys.stdin)
    except Exception:
        _allow()

    try:
        if data.get("tool_name") != "Bash":
            _allow()
        cmd = (data.get("tool_input") or {}).get("command", "")
        if not isinstance(cmd, str) or not cmd.strip():
            _allow()

        if _consume_marker(cmd):
            _allow()

        blocks = []

        if re.search(r"\bgit\s+push\b", cmd):
            if re.search(r"\b(master|main)\b", cmd):
                blocks.append("master/main으로의 git push")
            if re.search(r"--force(-with-lease)?\b|\s-f\b", cmd):
                blocks.append("git force-push")

        if re.search(r"\bgit\s+reset\s+--hard\b", cmd) and re.search(r"\b(origin|upstream)/", cmd):
            blocks.append("원격 ref로의 git reset --hard")

        if re.search(r"\brm\s+-\S*r\S*f|\brm\s+-\S*f\S*r|\brm\s+-rf|\brm\s+-fr", cmd):
            if re.search(r"(^|\s)(/|~|\$HOME)(\s|$|\"|')", cmd):
                blocks.append("홈/루트 대상 rm -rf")

        if blocks:
            sys.stderr.write(
                "BLOCKED by block_consequential.py: " + "; ".join(blocks) + ". "
                "정말 필요하면 오너가 검토한 뒤 신뢰된 발급 경로로 1회성 승인 "
                "마커를 발급하고 다시 실행해라.\n"
            )
            sys.exit(2)
    except Exception:
        _allow()
    _allow()


main()

settings.json 배선은 최소 버전과 같다 — 스크립트 내용만 바뀌었다.

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "python3 $HOME/.claude/hooks/block_consequential.py"
          }
        ]
      }
    ]
  }
}

직접 확인하는 법

아래 검사는 복사한 스크립트의 MARKER 상수를 임시 디렉터리 안의 경로로 바꾼 뒤 한다. 실제 ~/.claude 설정이나 마커를 수정하지 않는다. 위험 명령은 JSON 안의 텍스트로만 넘긴다. 훅은 이 문자열을 분류할 뿐 실행하지 않는다.

  1. 차단 확인. {"tool_name":"Bash","tool_input":{"command":"git push --force origin demo"}}를 복사한 훅의 stdin으로 넣는다. 종료코드 2와 차단 사유를 확인한다. 원격 push 자체는 실행하지 않는다.
  2. 마커 통과 확인. 복사한 발급 스크립트도 같은 임시 MARKER 경로를 쓰게 한다. 위 명령 문자열의 마커를 만들고 파일 모드 0600을 확인한다. 같은 JSON을 훅에 넣었을 때 종료코드 0인지 본다.
  3. 소비·재사용 거부. 마커가 사라졌는지 확인하고 같은 JSON을 다시 넣어 종료코드 2가 되는지 본다. 동시 호출 여러 개에도 유효한 마커 하나로 통과하는 소비자는 하나여야 한다.
  4. 정확한 바인딩·만료. 다른 명령 문자열, 만료 시각, 잘못된 권한의 마커를 각각 넣어 거부되는지 확인한다. 유효한 명령의 실제 실행은 이 검사의 범위가 아니다.
  5. 손상 입력. not json을 복사한 훅의 stdin으로 넣으면 이 fail-open 예제는 종료코드 0이 된다. 차단 기능이 실패하는 경우를 확인한 것이지 안전성이 입증된 것이 아니다.
  6. 문법 오류. 다른 복사본 첫 줄에 Python 문법 오류를 넣고 실행하면 종료코드 1이 된다. try/except가 실행되기 전의 오류라서 0으로 바뀌지 않는다. Claude Code에서 이를 비차단 오류로 처리하는지는 무해한 도구 호출과 설치 버전으로 별도 확인한다.

이 책의 기술 검증에서는 임시 파일과 JSON 입력으로 스크립트 동작을 확인했다. 실제 위험 명령이나 운영 중인 승인 체계를 시험한 것은 아니다.
