# 직접/위임 판정 체크리스트

『AI가 일했다는 증거』 4장(직접 할까 위임할까)의 체크리스트. 책 본문에서 그대로 뽑았다.
인쇄해서 옆에 붙여둘 것.

1. **지금 조작 가능한 축이 뭔가?** 위임을 본다면 "어느 워커냐" 하나뿐이다. 직접을 본다면 모델과 effort 두 개다. 없는 다이얼을 찾지 않는다.
2. **명세가 실행 가능한가?** 범위·완료조건·검증 방법이 안 정해졌다면 여기서 멈춘다 — `PLAN_FIRST`. 불분명한 목표로 비싼 실행을 낭비하면 그게 가장 비싼 실수다.
3. **물량이 작고 인계비용·컨텍스트의존도가 크다면** → `DIRECT`. 위임 고정비(새 컨텍스트 구축 + 명세 작성)가 산출물보다 크다.
4. **얕고, 검증 가능하고, 물량이 크고, 실패비용이 낮고, 명세가 확정됐고, 독립적으로 쪼개지고, 컨텍스트의존도가 낮다 — 일곱 조건 전부** 맞다면 "기계적 배치"다. 이때는 위임이 당연한 답은 아니다. 최적화 목표(비용/시간/컨텍스트 보존)를 먼저 정한다. 없으면 → `NEEDS_PREFERENCE`.
5. **명세 확정 + (물량 크거나 독립적으로 쪼개짐) + 독립 검증자 존재** → `DELEGATE`. 워커가 배차 설정에 고정된 모델·effort로 뛴다고 전제한다.
6. **직접 실행의 모델·effort를 정하려면 벤더 환경부터 확인한다.** 이 예제는 모델 선택을 구현하지 않으며 `NEEDS_SURFACE`도 반환하지 않는다.
7. **위임이 곧 저렴하다고 말하지 않는다.** 워커 가격뿐 아니라 캐시·토큰·검수 시간까지 함께 잰다. 직접-위임 실측 쌍이 없으면 비용 비교는 "측정되지 않음"이라고 정직하게 말한다.

제품 동작 근거: [서브에이전트 설정과 fork](https://code.claude.com/docs/en/sub-agents), [모델 설정](https://code.claude.com/docs/en/model-config), [캐시](https://code.claude.com/docs/en/prompt-caching). 확인 2026-09-28. 판정 함수는 입력을 검토할 예제이며 모델을 전환하거나 워커를 실행하지 않는다.

## 판정 축이 미는 방향

| 축 | 위임(DELEGATE) 쪽으로 미는 값 | 직접(DIRECT) 쪽으로 미는 값 |
|---|---|---|
| 검증가능성(verifiable) | yes — 결과를 기계적으로 확인 가능 | no — 판단이 주관적이라 위임 결과를 믿고 넘어가기 어려움 |
| 실패비용(failcost) | low/mid — 틀려도 되돌리기 쉬움 | high — 틀리면 파급이 커서 직접 통제하고 싶어짐 |
| 물량(volume) | high — 고정비를 상쇄할 만큼 큼 | low — 고정비가 산출물보다 큼 |
| 깊이(depth) | shallow — 반복적·기계적 | deep — 세션의 누적 맥락이 필요 |
| 인계비용(handoff_cost) | low — 브리프 작성이 짧게 끝남 | high — 명세 작성 자체가 큰 일 |
| 명세성숙도(spec_readiness) | executable — 넘길 게 확정돼 있음 | vague — 넘기기 전에 정해야 함(→ PLAN_FIRST) |
| 분해가능성(decomposability) | independent — 쪼개서 병렬로 맡길 수 있음 | single — 쪼개지지 않아 위임 이점이 없음 |
| 컨텍스트의존도(context_dependency) | low — 현재 대화의 암묵 지식이 필요 없음 | high — 위임받는 쪽이 그 맥락을 모름 |

## 이 예제의 판정 결과 네 가지

| 결과 | 뜻 |
|---|---|
| **DIRECT** | 지금 세션에서 직접 한다. 남은 선택은 모델·effort 두 축뿐이다. |
| **PLAN_FIRST** | 명세(범위·완료조건·검증자)가 아직 실행 가능한 상태가 아니다. 위임이든 직접이든 먼저 명세를 정한다. |
| **DELEGATE** | 다른 워커에게 맡긴다. 남은 선택은 어느 워커냐 하나뿐 — 그 워커의 모델·effort는 이미 고정돼 있다. |
| **NEEDS_PREFERENCE** | 조건은 다 갖췄지만 최적화 목표(비용/시간/컨텍스트 보존)가 없어 답을 하나로 좁힐 수 없다. 답을 지어내지 않고 되묻는다. |
