# 미션 승인 인터뷰

새 멀티에이전트 미션을 디스패치하기 전, 오너 전속 결정 네 가지를 확정하고
기록한다. 워커셋 자체는 오케스트레이터가 추천/자동선택하므로 여기서 묻지
않는다 — 여기서 묻는 건 오너가 아니면 답할 수 없는 결정뿐이다. 이 인터뷰는
미션마다 한 번 진행한다. 오너가 승인한 워커셋은 같은 미션 안에서는
target·scope·authority·blast-radius가 실질적으로 바뀌지 않는 한 재확인을
요구하지 않는다.

"쓸 수 있다"는 다른 결정이다 — 둘 다 명시한다.

- [ ] 읽기 전용 (리뷰·조사만, 쓰기 도구 자체를 안 준다)
- [ ] 격리된 워크트리/브랜치 안에서만 쓰기

## 결정 3 — 외부 효과 (Blast Radius)

이 미션의 실행이 이 세션 밖 무언가에 영향을 줄 수 있는가? (배포, 원격 브랜치
푸시, 외부 API 호출, 다른 사람이 보는 상태 변경 등)

- [ ] 없음 — 로컬/격리 환경 안에서 끝난다
- [ ] 있음, 승인 게이트를 통과해야만 실행 (6장 — 위험 명령 승인 게이트 참조)

## 결정 4 — 재검증 강도 (Reverification Strength)

워커의 결과를 얼마나 엄격하게 재검증할 것인가? (5장의 검증 등급 V0~V3,
0장의 증거 사다리 참조)

- [ ] V3 — 결정론적 테스트·스키마 검증 등 기계적 재현이 가능해야 통과
- [ ] V2 — 사람 또는 독립 리뷰어가 사전에 정한 완료조건에 대고 판단
- [ ] V1 — 감독 쪽의 구조화된 검토(리뷰 체크리스트 기반)
- [ ] 산출자의 자기보고만으로 충분 (사유를 반드시 남긴다 — 기본값으로 고르지

## Required Record — 자동조립

오너 답변 네 가지가 확정되면 아래에 조립해 미션 실행 기록에 남긴다. 이
레코드는 append-only로 보관한다 — 같은 미션 안에서 결정이 바뀌면 기존 줄을
지우지 말고 "YYYY-MM-DD 결정 N을 변경(사유)"로 추가한다.

```
mission: <미션 이름>
approved_at: <YYYY-MM-DD>
approved_by: <오너>
scope: <결정 1 답변>
write_boundary: <결정 2 답변>
blast_radius: <결정 3 답변>
reverification: <결정 4 답변>
worker_set: <추천된 워커셋, 오너가 바꿨다면 최종본>
```

## 최종 확인

오너가 위 네 결정과 워커셋을 최종 확인한 뒤에만 디스패치한다. 확인 없이
디스패치를 시작하지 않는다.

- [ ] 오너 최종 확인 완료 — 디스패치 가능
